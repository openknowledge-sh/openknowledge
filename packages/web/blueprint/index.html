THE FAILURE MODE

The code has a pipeline.
The explanation has a shelf life.

An answer can be well-written, easy to retrieve, and wrong. When documentation lives outside the engineering workflow, nobody knows what needs attention until someone relies on it.

THE OPEN KNOWLEDGE WORKFLOW

From “somewhere in the docs”
to something you can maintain.

01 / ADOPT

Start with the Markdown you have.

Discover existing docs, add the metadata and scaffold for a managed bundle, and keep editing in the tools you already use.

okn setup
02 / CHECK

Make knowledge quality inspectable.

Get one status across structure, links, and configured checks. Audit source changes and typed claim conflicts with concrete evidence.

okn check Wiki
03 / REVIEW

Repair the source of the answer.

Use audit findings to focus the change. Review it in Git. Add retrieval evaluations for important questions; connect an agent runner for answer comparisons.

okn audit Wiki
04 / PUBLISH

Give people and agents a shared foundation.

Publish checked knowledge to a configured static viewer or MCP runtime. Inspect the publication plan before you build.

okn publish Wiki --plan

okn setup

okn check Wiki
okn search Wiki "release workflow"
okn view Wiki
