Use cases / Research notes

Keep the findings. Keep the sources.

Turn source notes into linked findings you can revisit, question, and reuse in your next piece of work.

01

Separate evidence from interpretation

  • Sources: notes linked to the original material.
  • Findings: synthesis with citations and uncertainty.
  • Questions: what the sources do not establish yet.

Start from saved Markdown notes. Ask your agent to organize them and retain source references. Web capture and PDF extraction depend on your agent’s tools.

02

Build from your source notes

$okn setup Wiki --agent codex --from ./sources --rules research
Example result · after the agent completes setup
Wiki/
├── index.md
├── sources/
└── research/
    └── citation-workflow.md

An illustrative wiki structure. Codex builds the pages from your sources; filenames and agent output vary.

$okn search Wiki "what evidence supports the citation workflow?"
Example output · demo excerpt
Source: `research/citation-workflow.md:23-28`

The workflow should store the reviewed claim beside the source that directly
supports it.

Retrieve the finding together with its source location. Open the full page to inspect its citations.

The setup command uses an installed Codex agent. Use --prompt instead of --agent codex to get the task for an agent you already use. The example search question matches the demo below.

03

Return to the evidence

$okn view Wiki
Example output · local address varies
Open Knowledge view: http://127.0.0.1:4185/wiki/
root /your-project/Wiki
Press Ctrl+C to stop.

Opens the local viewer in your browser so you can browse, search, and edit the Markdown.

$okn review Wiki --scope full
Example output · copied review task excerpt
# Open Knowledge Content Review

Review scope: `full`
Deterministic validation: 0 errors, 0 warnings.

Treat findings as advisory.

The task covers all Markdown pages. Your selected agent reviews the content and evidence.

Browse findings beside source notes. When new material disagrees, ask the agent to revise the synthesis and keep the disagreement explicit. Review the diff before you commit.
