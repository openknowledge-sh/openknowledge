A clear answer is not enough

Research often ends in a chat message or short summary. The answer remains, but the source trail disappears. Later, nobody knows which statements came from evidence.

  • The sources disappear.Links, files, and quotes stay in a browser session or AI chat.
  • A guess can look like a fact.A confident summary may hide weak evidence or important limits.
  • The next person starts again.Another person or AI agent repeats the search because no useful record exists.

A research finding becomes useful when a reader can follow it back to its source.

First, set up Open Knowledge

Store the research as simple Markdown files in the project. Then add the built-in research rule to the AI agent instructions.

  1. Install Open Knowledge

    If okn version already works, skip this command.

    $ curl -fsSL https://openknowledge.sh/install | bash

  2. Create the knowledge base

    Start the guided setup in the project that will use the research.

    $ okn setup Wiki --interactive

  3. Add the research rule

    Add the rule to the project instructions.

    $ okn prompt rules apply research --path Wiki --file AGENTS.md

The rule keeps source notes separate from the summary. It keeps source links with each finding. It also keeps unsupported ideas out of confirmed project knowledge.

Show where each finding came from

Open Knowledge can store source details with each research page. Each source needs a web link or file path. An optional ID connects a finding to the right source. 

---
type: Research Note
title: Citation workflow comparison
status: draft
sources:
  - id: editor-interviews
    resource: ../sources/editor-interviews.md
    title: Editor interview notes
  - id: tool-docs
    resource: ../sources/citation-tool-docs.md
    title: Citation tool documentation
---

# Findings

The first workflow should preserve a source URL and the
claim it supports.[^editor-interviews]

# Limits

The current evidence does not cover mobile editing.

[^editor-interviews]: Editor interview notes.

This example is not real research. It shows one finding, one source ID, and one clear limit. The limit remains visible to every reader.

Give the AI agent a simple research process

Start the task with a clear question. End it with a research note that another person can check. Save each source during the research. 

For this research task:
1. Write the question and its limit.
2. Save links, files, and quotes in source notes.
3. Link each finding to its source.
4. Separate facts, possible conclusions, limits, and questions.
5. Do not treat an unsupported idea as a fact.

The rule does not decide if a source is trustworthy. It keeps the source available so a person can judge the finding.

Find the evidence again

A person or AI agent can search the knowledge base later. Search runs on the local computer and shows the exact files and sections behind each result. 

$ okn search Wiki "what evidence supports the citation workflow?"

The result can include the research summary and its linked source notes. The reader can then open the original source record.

Review the facts and the limits

Review the note before the project depends on it. A clear paragraph can still say more than its sources support.

  • Does each finding link to a source?
  • Does the note separate facts from possible conclusions?
  • Does the note show limits and unanswered questions?
  • Does Open Knowledge report valid files and links?
$ okn validate Wiki

Validation checks file structure, document details, Markdown, and local links. It does not prove that a source or finding is correct.

The next question starts with useful sources

You do not need to save every browser tab. Save the smallest useful path from each finding back to its source.

  • Less repeated researchPeople and AI agents can reuse a reviewed set of sources.
  • Clear limitsLimits and open questions remain part of the research note.
  • One clear reviewA reviewer can check the sources and findings together.
