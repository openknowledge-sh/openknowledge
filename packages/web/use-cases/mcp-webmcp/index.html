Use cases / MCP + WebMCP

Your wiki.
Work with your agent.

Create your wiki once. Let an agent find context through local MCP, or open the viewer and work on the same pages together through WebMCP.

01

Start with your knowledge

You or your coding agent can start setup from the repository.

$okn setup
Example output · after confirming a copy
Knowledge base created at /your-project/Wiki.
Documents       3
Validation      READY
Search index    READY (5 hits)

The same local Markdown wiki works with both connections below.

Select existing Markdown to copy or adopt. Starting from scratch? Setup prepares a task for your installed agent to build the wiki.

02

Work together in the browser

WebMCP / shared viewer

Open the wiki locally. A compatible browser agent can use its tools and work in the same editor you see.

$okn view Wiki
Example output · address varies
Open Knowledge view: http://127.0.0.1:4185/wiki/
root /your-project/Wiki
Press Ctrl+C to stop.

The command opens your browser. Keep the viewer running while you and your agent use it.

  1. Open the viewer with your browser agent.

    The page exposes WebMCP tools for listing, searching, reading, and opening wiki pages.

    openknowledge_search → openknowledge_open_page
  2. Make the change in one shared draft.

    The agent reads the current editor state and edits the Markdown. Its changes appear in your editor, with a shared Undo history.

    openknowledge_get_editor_state → openknowledge_apply_edit
  3. Review the change, then save.

    Inspect Changes and click Save, or ask the agent to save. Draft edits only reach the existing Markdown file when saving succeeds.

    openknowledge_save_document
Bring a WebMCP-capable browser and agent.

WebMCP support is still evolving. The local page registers its tools when the browser provides the API; the agent must support discovering and calling them. No separate Open Knowledge MCP server configuration is needed for this route.

Browser API and availability ↗

Shared editing works on existing writable Markdown pages in the local viewer. Static viewer exports expose browsing tools only. Browsers without WebMCP still work as ordinary viewers.

04

Connect from your agent client

Local MCP / read-only context

Use this route when your agent needs wiki context from an editor or desktop client, without opening a browser.

$okn mcp /absolute/path/to/Wiki
Protocol server · not a chat command
stdin / stdout ↔ your MCP client

The client normally starts this process. It exchanges MCP messages over stdio, so running it alone does not print a human-readable search result.

Example client configuration
{
  "mcpServers": {
    "project-knowledge": {
      "command": "okn",
      "args": ["mcp", "/absolute/path/to/Wiki"]
    }
  }
}

Install okn where the client can run it and replace the absolute path with your wiki location. Add this server in your client's MCP settings; the configuration format depends on the client.

Ask for relevant context

The client can search and read wiki sources, run explicit semantic queries, and validate the bundle.

Keep writes explicit

This MCP server is read-only. It does not edit files. Use the local viewer or your agent's file tools for changes.
